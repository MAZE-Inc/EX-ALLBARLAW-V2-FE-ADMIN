# DG02. SW 아키텍처 설계서

## 1. 개요

### 1.1 문서 목적
본 문서는 올바로(Allbarlaw) 관리자용 프론트엔드 애플리케이션의 소프트웨어 아키텍처를 정의합니다.

### 1.2 프로젝트 정보
- **프로젝트명**: EX-ALLBARLAW-V2-FE-ADMIN
- **프로젝트 유형**: 관리자용 웹 프론트엔드
- **대상 사용자**: 시스템 관리자

---

## 2. 아키텍처 원칙

### 2.1 설계 원칙
| 원칙 | 설명 |
|------|------|
| 컴포넌트 기반 설계 | React 컴포넌트를 활용한 재사용 가능한 UI 구성 |
| 관심사 분리 | 비즈니스 로직, UI, 상태 관리를 명확히 분리 |
| 타입 안정성 | TypeScript를 통한 컴파일 타임 타입 검사 |
| 관리자 UX 최적화 | Ant Design 기반 일관된 관리자 UI |

### 2.2 아키텍처 패턴
- **SPA (Single Page Application)**: React Router를 활용한 클라이언트 사이드 라우팅
- **Container-Presenter 패턴**: 비즈니스 로직과 UI 분리
- **서버 상태 관리**: React Query를 활용한 데이터 페칭 및 캐싱

---

## 4. 주요 기능 영역

### 4.1 관리 기능
| 영역 | 기능 |
|------|------|
| 관리자 관리 | 관리자 계정 CRUD |
| 회원 관리 | 일반 회원/변호사 회원 관리 |
| 컨텐츠 관리 | 블로그/영상/법률지식 관리 |
| 게시판 관리 | 공지사항/FAQ/법률용어사전 관리 |
| 카테고리 관리 | 법률 분야 카테고리 관리 |
| 광고 관리 | 배너/로펌/변호사 광고 관리 |
| 채팅 관리 | 바로톡 채팅 모니터링 |
| 통계 | 서비스 이용 통계 |

## 5. 라우팅 구조

### 5.1 주요 라우트
| 경로 | 페이지 | 설명 |
|------|--------|------|
| `/login` | 로그인 | 관리자 로그인 |
| `/admin` | 관리자 관리 | 관리자 계정 관리 |
| `/category` | 카테고리 관리 | 법률 분야 카테고리 |
| `/lawyer` | 변호사 관리 | 변호사 회원 관리 |
| `/member` | 회원 관리 | 일반 회원 관리 |
| `/content/blog` | 블로그 관리 | 블로그 컨텐츠 CRUD |
| `/content/video` | 영상 관리 | 영상 컨텐츠 CRUD |
| `/content/knowledge` | 법률지식 관리 | 법률지식 조회 |
| `/board/notice` | 공지사항 관리 | 공지사항 CRUD |
| `/board/faq` | FAQ 관리 | FAQ CRUD |
| `/board/legal-dictionary` | 법률용어사전 | 법률용어 CRUD |
| `/ad/*` | 광고 관리 | 배너/로펌/변호사 광고 |
| `/chat-list` | 채팅 관리 | 채팅 목록 조회 |
| `/statistics` | 통계 | 서비스 통계 |

### 5.2 라우트 보호
- `ProtectedRoute`: 인증된 관리자만 접근 가능
- `PublicOnlyRoute`: 비로그인 상태에서만 접근 (로그인 페이지)

## 7. 비기능 요구사항

### 7.1 성능
- 페이지 로딩 시간: 3초 이내
- React Query를 통한 데이터 캐싱
- 테이블 데이터 페이지네이션

### 7.2 보안
- 관리자 인증 필수
- 세션 기반 인증
- HTTPS 통신

### 7.3 사용성
- Ant Design 기반 일관된 UI
- 반응형 레이아웃 (사이드바 접기)
- 테이블 정렬/검색/필터링
